Finalize the website direction before building the real application. The user subsequently approved the soft mauve makeup-texture direction and explicitly requested its website build and a commit.

**Why:** The user wants to approve the complete flow first and dislikes the original homepage.

**How to apply:** The approved direction is now authorized for implementation. Do not reinterpret that authorization as permission to publish or to replace the owner's Supabase project.

Use review branches by default. The owner explicitly authorized pushing the approved website and repository organization to GitHub main, but not publishing or unrelated future main pushes.

**Why:** The owner initially required review, then explicitly asked to push the approved work to main and organize the repository.

**How to apply:** Preserve the existing native app and legacy website when integrating the approved website into main. Leave hosting and database changes for separate approval. Future unrelated work remains review-first.

The website needs an education section explaining undertones and color theory, so it is one place for people.

**Why:** The user explicitly requested education alongside makeup discovery.

**How to apply:** Include learning within the website navigation and connect it to tone/profile and product exploration.

Do not use em dashes anywhere in the Neu website or its previews.

**Why:** The user repeated that they should not see any of these in the whole thing.

**How to apply:** Use periods, commas, colons, or parentheses instead, and check all Neu preview copy rather than only the selected frame.

Keep makeup imagery unbranded. Do not reintroduce animated product illustrations without a request.

**Why:** After exploring product animations, the user explicitly asked for the shared image instead of the current product illustration.

**How to apply:** The later feedback below supersedes the earlier choice of colorful artwork; the restriction on unwanted product animation still applies.

The user likes the Color Studio homepage direction, but does not want the dome-shaped artwork container.

**Why:** The user explicitly confirmed the direction and requested removal of the dome shape.

**How to apply:** Preserve that direction when refining Color Studio; use a rectangular artwork area rather than an arched silhouette.

The homepage should express makeup as outspoken self-expression: keep the colors soft, but get boldness out of that softness.

**Why:** The user wants Neu to feel confident and true to itself like makeup brands, rather than quiet because of its soft palette.

**How to apply:** Preserve the latest approved soft palette and imagery while making homepage presentation and language expressive and confident.

The user later said the colorful picture does not go with the homepage and that they liked their color palette from before.

**Why:** The user wants better picture directions without losing the earlier soft palette.

**How to apply:** Keep cream, dusty rose, mauve and plum as the comparison baseline. Explore new picture subjects separately from palette changes; do not treat the colorful still life as locked.

Keep homepage imagery embedded in the page rather than boxed. Keep the image clean, without tone-profile or recommendation overlays.

**Why:** The user disliked boxing the picture and said the “Tan · Olive” overlay was interfering with it.

**How to apply:** Blend image edges into the page and place profile information in its own flow, not over homepage artwork. On mobile, keep the artwork full-width in the document flow, not a narrow detached picture below the copy.

The user considers the soft mauve makeup-texture direction finalized and wants cleanup rather than more visual alternatives.

**Why:** After refining the embedded image, the user said the direction was finalized, then explicitly requested consistency throughout and a Neu design system.

**How to apply:** Refine this direction without unsolicited new variants. Use the shared Neu design system rather than independent page palettes. Keep navigation uncluttered, Learn accessible, imagery embedded, and spacing comfortable without excessive empty space. Remove the rejected “beauty in your own tone” tagline and visible “CONCEPT IMAGE” labels from homepage artwork.

Let users type a brand and autocomplete it rather than making them choose from a fixed dropdown menu.

**Why:** The user explicitly corrected the brand-entry interaction.

**How to apply:** Preserve type-to-search brand entry when refining the quiz. Do not replace it with a fixed select menu.

Quiz screens should be compact, centered consultation steps, not long marketing sections with repeated explanatory panels, repeated questions or multiple result summaries.

**Why:** The user said the preview was “way off,” supplied a clean quiz reference, and later emphasized that there were too many repetitions and the experience still felt off.

**How to apply:** Keep one short question, concise help, compact choices and simple Back/Continue controls. Avoid excessive space and lengthy stacking on mobile while retaining readable text and accessible targets.

Keep the consultation compact, with progressive optional details and one combined outcome. The accepted web MVP specification now makes complexion depth the first question and olive a first-class undertone choice.

**Why:** The owner rejected repetitive flows, then explicitly instructed us to follow the updated web MVP specification while preserving Neu's design and existing functionality.

**How to apply:** Start with depth, retain typed optional makeup history and fit notes, offer olive temperature/saturation and lip preferences progressively, and finish with one editable profile and evidence-aware browsing. Keep uncertainty valid. Do not reintroduce mandatory vein tests, repeated technical questions or multiple results endings.
